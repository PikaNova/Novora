# 教室端运行日志一期

教室端运行日志服务于学校运维定位问题，覆盖前端显示、校时观察、同步数据、设备命令、通知、网络、页面生命周期、PWA 和本地存储状态。日志只记录诊断所需的结构化信息，不记录学生姓名、试题内容、通知正文、访问令牌或原始业务对象。

## 本地记录

`src/utils/runtimeJournal.ts` 负责生成会话 ID、事件序号、墙上时间和单调时间，并在保存前统一脱敏。日志优先写入 IndexedDB，批量提交；IndexedDB 不可用时降级到受限的 localStorage 恢复区和内存。保留上限为 7 天、5000 条和 8 MiB，异常现场会保存异常前后窗口。刷新、隐藏页面和 pagehide 会立即保存恢复证据。

## 事件范围

- `display`：显示选择、提交、布局和全屏状态。
- `time`：校时样本、校时状态，以及系统时间或显示基准的异常观察；不修改校时算法。
- `sync`：拉取、版本、应用或忽略原因、同步状态和请求关联 ID。
- `device`：设备绑定、心跳、命令接收/应用/失败和日志收集。
- `notice`：公告触发、过期跳过、提醒展示和确认结果。
- `network`、`page`、`pwa`、`storage`：请求、页面错误、资源失败、Promise 拒绝、生命周期、Service Worker 和日志存储状态。

显示状态与同步数据版本通过共享快照关联；只有版本锚点一致时才关联操作 ID，避免把旧数据的显示问题归因到新数据。

## 学校后台收集流程

设备首次启动生成并持久化设备密钥，向后台申请登记。管理员批准具体登记后，教室端按轮询领取仅属于本设备的收集任务，读取本地保留范围并按不超过 250 条/约 450 KiB 分批上传。所有分批上传成功后才确认任务完成；失败会保留任务和本地证据，后续可幂等重放。收集结果会说明本地保留期、容量或降级存储造成的潜在缺失，不伪造完整历史。

## 当前边界

一期提供本地结构化日志和后台主动收集所需的设备客户端；后台审批、查询、导出和仪表盘由另一条对话实现。浏览器没有 IndexedDB 时的测试覆盖降级存储路径，真实浏览器 IndexedDB 行为仍应在集成环境验证。
