# 全量备份与恢复

## 入口与权限

设置 → 数据与维护 → 全量备份与恢复。仅不需要修改密码、具有全部学校范围和通配权限的超级管理员可以查看和操作。所有成功的手动、自动、恢复前保护备份都提供下载；Windows 模式中已有的有效 `.dump` 文件也逐份提供下载。列表每页 50 条，可继续加载。

## 备份范围

学校服务端业务全量：学校/年级/班级与考试快照、考试记录及生命周期操作、账号角色和权限范围、设备和插件绑定、学校公告及数据库内图片/回执/模板、时间控制与诊断设置。外部图片 URL 仍为 URL，不会下载远程资源。

不包含部署环境变量、数据库连接串、邮件或平台密钥、目标实例恢复配置、运行日志和队列、备份列表和自动任务设置、浏览器偏好与离线草稿。恢复保留目标环境的存储和调度配置。恢复后的账号和密码来自备份。

Web 文件为 UTF-8 JSON，扩展名 `.novora-backup`；最大 20 MiB，上传/下载以 512 KiB 分块。SHA-256 覆盖元数据与数据，用于损坏检测，并非签名或加密。文件包含账号哈希与学校敏感数据，下载后请妥善保存。只接受相同数据库结构的备份，不提供跨结构迁移、增量备份或文件密码加密。

## Web 手动与自动备份

手动备份也必须先配置持久存储。快照以数据库表锁保证一致性，文件保存后回读验证，成功后显示下载按钮。失败记录可见，不把未完成文件标为成功。

自动备份默认关闭，开启后按 Asia/Shanghai 日期每天成功一次。默认保留最近 14 份成功的自动备份，可配置 1–365 份。手动和恢复前保护备份不参与自动轮转，可在界面确认后单独删除。新文件验证成功后才清理旧文件；清理失败写服务端日志，保留已成功的备份。并发操作通过数据库 10 分钟租约互斥，过期运行记录显示任务中断。

### Vercel

配置私有 Vercel Blob 的 `BLOB_READ_WRITE_TOKEN`，以及至少 16 位的 `CRON_SECRET`。`vercel.json` 每日 UTC 00:00（上海时间 08:00）调用 `/api/backups`，使用 Bearer secret 验证；未配置密钥不开放任务接口。文件保存在私有 Blob，不依赖函数本地磁盘。

Vercel Functions 当前单次请求或响应 body 上限为 4.5 MB；本项目用 512 KiB 分块，因此 20 MiB 是多次请求的应用层上限，不会把 20 MiB 作为一次函数请求发送。20 MiB 也不是 Vercel Blob 的单文件上限，但函数恢复会在内存中组装快照并受函数时长、内存和请求次数影响；备份数量还会产生 Blob 存储和读写费用。后续若备份持续增长，应改为客户端直传 Blob、流式/后台任务或数据库原生备份，而不是只提高这个阈值。

界面的调度就绪状态仅检查环境配置，不代表真实运行健康检查。发布前需在目标 Vercel 项目验证 Cron、套餐时限和私有 Blob 读写删除。首版没有应用内 Vercel 自动重试；失败后可手动备份，或等待后续定时触发。

### Docker / NAS

Compose 中 Web 服务与独立 backup-worker 共享备份持久卷。Worker 启动时检查一次，此后每 15 分钟检查；当日已成功时跳过，失败可在下一次检查重试。开启开关后才生成自动备份。

非 Docker 的 Node 部署，Web 与 worker 使用相同数据库及持久目录：

```dotenv
BACKUP_STORAGE_DIR=/var/lib/novora/backups
BACKUP_WORKER_ENABLED=1
```

构建服务端后启动独立进程 `node server-build/server/backupWorker.js`，并由宿主机进程管理器守护。`BACKUP_WORKER_ENABLED=1` 只是配置标记，不会自动启动进程。目录须允许服务读写，容器重建后仍然存在；异地复制由宿主机负责。

## Windows 安装版

创建、自动计划和恢复继续使用原客户端控制中心。Web 设置提供已有数据库备份的列表和下载，保留原文件名，不启动第二套调度器，也不在 Web 中导入 `.dump`。

在安装版服务环境中配置并重启服务：

```dotenv
NOVORA_BACKUP_MODE=windows
NOVORA_WINDOWS_BACKUP_DIR=C:\ProgramData\Novora\backups
```

目录默认即 `%ProgramData%\Novora\backups`；自定义时须与控制中心的备份目录一致，Web 服务账户需有读取权限。只列出普通 `novora-*.dump` 文件，跳过临时文件、目录和符号链接，下载时校验目录边界及文件标识。

本次修改位于主项目，未修改独立 Windows 安装器仓库，因此已有安装版需要显式设置上述环境变量。Web `.novora-backup` 与控制中心 `.dump` 格式不互通。浏览器分块接收后在内存组装下载，大型 dump 建议直接从控制中心或备份目录复制。

## 恢复流程

1. 选择本地 `.novora-backup` 上传，校验格式、SHA-256、数据库结构、完整列和可用超级管理员账号，预览时间、大小、管理员以及按业务名称展示的内容项数量。
2. 输入当前超级管理员密码及 `RESTORE`，再次确认覆盖。
3. 建立维护租约阻止普通业务写入，先创建并验证一份可下载的恢复前保护备份；保存失败则不覆盖。
4. 单个数据库事务替换业务数据、清空运行队列、更新修订和序列、轮换会话签名密钥。事务失败回滚原数据及签名密钥，保护备份仍保留并可下载。
5. 成功后使所有旧会话失效，需使用备份中的账号重新登录。保留目标实例原有加密密钥；恢复代际标记阻止旧离线草稿自动回写。结束后维持 10 秒写入缓冲期，随后恢复业务写入。

数据库级一致性不等于部署验证。上线前应分别在目标 Vercel 和 NAS 环境演练创建、自动任务、下载与恢复；定期使用测试实例验证下载文件可恢复。
