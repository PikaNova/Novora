# 全量备份与恢复

## 入口与权限

设置 → 数据与维护 → 全量备份与恢复。仅不需要修改密码、具有全部学校范围和通配权限的超级管理员可以查看和操作。Linux 自部署的成功备份可从列表下载；Vercel 生成备份时立即下载；Windows 模式中已有的有效 `.dump` 文件逐份提供下载。Web 备份下载会同时生成 `.sha256` 校验文件。

## 备份范围

学校服务端业务全量：学校/年级/班级与考试快照、考试记录及生命周期操作、账号角色和权限范围、设备和插件绑定、学校公告及数据库内图片/回执/模板、时间控制与诊断设置。外部图片 URL 仍为 URL，不会下载远程资源。

不包含部署环境变量、数据库连接串、邮件或平台密钥、目标实例恢复配置、运行日志和队列、备份列表和自动任务设置、浏览器偏好与离线草稿。恢复保留目标环境的存储和调度配置。恢复后的账号和密码来自备份。

Web 文件为 UTF-8 JSON，扩展名 `.novora-backup`。传输以 512 KiB 分块，下载时浏览器会校验完整文件的 SHA-256，并提供独立校验文件。文件同时包含内部 checksum，用于发现损坏；SHA-256 是完整性校验值，并非数字签名或加密。文件包含账号哈希与学校敏感数据，下载后请妥善保存。只接受相同数据库结构的备份，不提供跨结构迁移、增量备份或文件密码加密。

## Vercel：生成后立即下载

点击“生成并下载备份”后，系统在当前请求中生成完整快照，并下载 `.novora-backup` 和对应的 `.sha256` 文件。Vercel 不提供定时备份或可再次下载的云端文件；长期记录仅包含文件 SHA-256 和备份元数据。

为避开 Vercel 单次请求/响应体积限制，文件经 512 KiB 分块传输。生成期间分块会临时暂存，下载完成并校验后立即删除；未完成的暂存数据设置 30 分钟有效期，并在后续备份操作时清理。恢复时先上传并验证所选文件，再生成恢复前保护备份并下载这份文件及其 `.sha256`，然后才执行恢复。恢复请求会再次比较上传文件签名和保护备份签名。

Vercel 备份文件上限为 20 MiB。创建与恢复耗时还受数据库、函数运行时间和内存限制；如果生成或下载中断，重新执行操作即可。Vercel 不调用备份 Cron，也不需要 Blob 存储配置。

## Linux 自部署：本地目录

Web 手动备份和恢复前保护备份保存在 `BACKUP_STORAGE_DIR`。Linux 默认最大 128 MiB，可通过 `BACKUP_MAX_BYTES` 设置为 20 MiB 至 2 GiB；目录须允许服务读写，并在容器重建后仍然存在。异地复制由宿主机负责。

自动备份默认关闭，开启后按 Asia/Shanghai 日期每天成功一次。默认保留最近 14 份成功的自动备份，可配置 1–365 份。手动和恢复前保护备份不参与自动轮转，可在界面确认后单独删除。新文件验证成功后才清理旧文件；清理失败写服务端日志，保留已成功的备份。并发操作通过数据库 10 分钟租约互斥，过期运行记录显示任务中断。

Docker Compose 中 Web 服务与独立 backup-worker 共享备份持久卷。Worker 启动时检查一次，此后每 15 分钟检查；当日已成功时跳过，失败可在下一次检查重试。开启开关后才生成自动备份。

非 Docker 的 Node 部署，Web 与 worker 使用相同数据库及持久目录：

```dotenv
BACKUP_STORAGE_DIR=/var/lib/novora/backups
BACKUP_MAX_BYTES=134217728
BACKUP_WORKER_ENABLED=1
```

构建服务端后启动独立进程 `node server-build/server/backupWorker.js`，并由宿主机进程管理器守护。`BACKUP_WORKER_ENABLED=1` 只是配置标记，不会自动启动进程。

## Windows 安装版

创建、自动计划和恢复继续使用原客户端控制中心。Web 设置提供已有数据库备份的列表、下载和 SHA-256 校验文件，不启动第二套调度器，也不在 Web 中导入 `.dump`。

在安装版服务环境中配置并重启服务：

```dotenv
NOVORA_BACKUP_MODE=windows
NOVORA_WINDOWS_BACKUP_DIR=C:\ProgramData\Novora\backups
```

目录默认即 `%ProgramData%\Novora\backups`；自定义时须与控制中心的备份目录一致，Web 服务账户需有读取权限。只列出普通 `novora-*.dump` 文件，跳过临时文件、目录和符号链接，下载时校验目录边界及文件标识。

本次修改位于主项目，未修改独立 Windows 安装器仓库，因此已有安装版需要显式设置上述环境变量。Web `.novora-backup` 与控制中心 `.dump` 格式不互通。浏览器分块接收后在内存组装下载，大型 dump 建议直接从控制中心或备份目录复制。

## 恢复流程

1. 选择本地 `.novora-backup` 上传；校验文件 SHA-256、内部 checksum、数据库结构、完整列和可用超级管理员账号，并预览创建时间、大小、管理员及按业务名称展示的内容项数量。
2. 输入当前超级管理员密码及 `RESTORE`，再次确认覆盖。
3. 建立维护租约阻止普通业务写入。Linux 自部署先创建并保存保护备份；Vercel 先生成并下载保护备份及 SHA-256 校验文件。保护备份未完成校验时不执行覆盖。
4. 单个数据库事务替换业务数据、清空运行队列、更新修订和序列、轮换会话签名密钥。事务失败时回滚原数据及签名密钥。
5. 成功后使所有旧会话失效，需使用备份中的账号重新登录。保留目标实例原有加密密钥；恢复代际标记阻止旧离线草稿自动回写。结束后维持 10 秒写入缓冲期，随后恢复业务写入。

数据库级一致性不等于部署验证。上线前应分别在目标 Vercel 和 Linux 自部署环境演练创建、下载与恢复，并在 Windows 控制中心验证原有 `.dump` 流程；定期使用测试实例验证下载文件可恢复。
