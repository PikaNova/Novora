# Novora 完整版本任务规划（三端并行，v2.7.x → v4.0+）

基线：`novora-remote-audit`，`main`，`0850b00`，版本 `2.7.3`。

本规划依据三份对话（未来项目规划、版本规划整合、考试功能规划）与架构审查、代码质量报告合并而成。核心原则：

1. **三端严格分离**：客户端 Client、学校服务端 School Server、作者端 Author Center。Agent 是客户端侧组件，不是第四个产品端。
2. **每个版本三条轨道并行**：客户端任务、学校服务端任务、作者端任务同步推进。
3. **版本号由验收条件驱动**，不由日期驱动；每阶段有明确出口条件。
4. **学校数据留在学校服务端**，作者端只收脱敏的实例级统计，不读考试正文。

## 产品架构

```text
                Novora 作者端 Author Center
            版本中心 | 错误中心 | 实例中心 | 运维中心
                         │
                  软件生命周期 / 授权 / 更新
                         │
        ┌────────────────┴────────────────┐
        │                                 │
  Novora 学校服务端                 Novora Agent
  School Server                    Windows / Linux
        │                                 │
        └──────────────┬──────────────────┘
                       │
              学校客户端（教室大屏）
        考试显示 | 管理后台 | 设备状态
```

| T-287-02 ✅ | 服务端 | 保存请求校验改为「至少携带一个可写域」 | 只带周测/班级的提交返回 200；`items` 非数组仍 400 |

| T-287-06 ✅ | 客户端 | 镜像字段同组判定（`items`/`title` 随 `majors[active]`） | 该组未变化时三个字段都不发 |

**出口条件**：平均提交字节数下降 ≥50%；no-op 提交归零；一次编辑动作 ≤1 次写；
旧客户端（整份提交）零回归；`verify:fast` 通过。

**2026-09-25 落地结果**：`npm test` 713 通过 / 0 失败，`npm run test:integration` 真实库 56 通过 / 0 失败，
`typecheck:api` + `build` + 改动文件 lint/format 通过。实测（整份提交 67.3 KB 基线）：
改班级名 4.2 KB（−93.8%）、改考试时间 5.0 KB（−92.5%）、只改运行模式 −99.9%；
改一个周测格子只省 15.4%，说明周测应作为阶段 C 的首个记录级写目标。

**A 段不做**：不拆表、不改 ETag、不改 409 语义、不改 outbox payload 结构。

                │                                              │
                └──→ v3.0.x ─→ v3.1.x ─→ v3.2.x ─→ v3.3.x ─→ v4.0+

v2.9.x 可在 v2.8.5 稳定后并行设计设备模型，但合并须在 v2.8.x 完成后。v2.12 Agent 需要 v2.9 设备身份和 v2.11 远程授权同时稳定。

## 发布检查清单（每个版本）

1. `npm test` 全部通过。
2. `npm run typecheck:api` 通过。
3. `npm run build` + `npm run serve:build` 通过。
4. `npm run format:check` 通过。
5. 独立数据库集成测试通过（涉及 schema 变更时）。
6. 旧客户端兼容性回归（涉及 API 变更时）。
7. 审计日志覆盖新操作（涉及设备/权限变更时）。
8. 迁移/回滚脚本在集成环境验证（涉及 schema 变更时）。
9. 版本号、CHANGELOG、README 同步更新。
10. 三端改动各自有测试；学校数据不出服务端边界。
