# Novora 商业化分层：免费与收费的功能边界

> 状态：待评审。只定分层与架构位置，不含实现改动。
> 核心结论：Agent 是收费核心；授权与支付分离；数据与安全能力永远免费。

## 1. 一条分界线

**"让一间教室正常上课"的功能免费；"让一个人管住整个学校 / 多校区"的功能收费。**

## 2. 分层原则（三条底线）

1. **不锁数据、不锁安全**：数据导出、备份、恢复、升级回滚、基础错误上报永久免费。收费只落在"规模、远程与自动化能力、内容"三个轴。
2. **Agent 组件免费、Agent 能力收费**：安装包免费铺量（扩大装机、获取运行数据），收费的是它之上的批量控制、远程诊断、自动更新策略、异常自愈。
3. **到期只停付费能力**：考试、大屏、数据读写与导出始终可用，不出现"数据被锁死"。

## 3. 现状能力归属

| 现有能力 | 归属 | 说明 |
|---|---|---|
| 大型考试（创建/编辑/快速发布/导入/导出） | 免费 | 产品本体 |
| 周测计划（复制/覆盖/导入/导出/PDF） | 免费 | 产品本体 |
| 年级与班级、运行模式、冲突策略、提醒 | 免费 | 基础教学配置 |
| 教室大屏（显示/时钟/公告/全屏/离线重发） | 免费 | 装机量基础 |
| 数据导出（JSON / PDF / 打印） | 免费 | 学校自有数据 |
| 备份 / 恢复 / 升级 / 回滚 | 免费 | 安全兜底 |
| 设备绑定与撤销、心跳、在线判定 | 免费（≤ 5 台） | 试用与小规模必需 |
| 单台考试控制指令（暂停/继续/延时/结束） | 免费 | 已是现状功能，不可回收再收费 |
| 基础错误上报 + 手动诊断包上传 | 免费 | 作者端运维的输入源 |
| 用户 / 角色 / 审计（基础） | 免费 | 学校内控必需 |
| Agent 远程能力（批量下发、远程诊断、自动更新策略、异常自愈） | **收费·核心** | 价值随装机规模增长 |
| 设备规模超出免费额度 | 收费 | 与 Agent 装机数一致的分层轴 |
| 楼栋/教室空间模型、教室状态总览 | 收费 | 中大型学校需求 |
| 作者端高级运维（跨实例统计、灰度发布、版本分组、远程诊断授权） | 收费 | 多校区/深度运维 |
| 内容包（考试模板、设计皮肤、学科素材、AI 解析） | 收费·可单独订阅 | 可持续产出 |
| 楼控（空调/灯光/门锁）、远程控制 L2/L3 | 收费·企业版 | 硬件依赖、高风险高价值 |
| 多校区/多租户、开放 API、审计留存延长 | 收费·企业版 | 大客户专属 |

## 5. 授权模型（代码落点）

```
支付系统 → 订单 → License → Entitlement → 功能权限
```

功能代码只读 Entitlement，不读支付状态，不出现散落的 `if (isPaid)`。

License 字段：`id / schoolId / plan / status / issuedAt / expiresAt / maxDevices / features[]`

状态机：`ACTIVE → EXPIRING → EXPIRED → GRACE_PERIOD → LIMITED`

统一判断入口（建议命名）：

| 标识 | 含义 |
|---|---|
| `agent.remote` | Agent 远程指令与批量下发 |
| `agent.autoupdate` | Agent 自动更新策略 |
| `space.multi_building` | 多楼栋空间模型 |
| `content.pack` | 内容包 |
| `ops.cross_instance` | 作者端跨实例统计 |
| `ops.canary` | 灰度发布 |
| `building_control` | 楼控与远程控制 |

超限策略：设备数超限走**软限制**——提示 + 30 天宽限 + 只读，不硬断教学。

## 6. 版本映射

| 版本 | 商业化相关动作 |
|---|---|
| v2.8 及以前 | 完全不碰收费代码 |
| v2.9.x | 设备身份 / 心跳 / 错误中心（Agent 前置，仍免费） |
| v2.10.x | 镜像分发 + 版本中心 + 更新/回滚 + 备份恢复（Agent 的部署与升级通道） |
| v2.11.x | 埋入 License / Entitlement / Feature Flag 数据结构与 `canUse()` 入口；**内测期免费签发、全功能打开** |
| v2.12.x | Agent 交付并稳定（注册密钥、撤销、恢复、Windows 优先、远程控制 L1/L2/L3 分级） |
| v3.0–v3.2 | 授权底层稳定：到期、宽限、设备数上限生效 |
| v3.3 | 正式启用套餐与功能限制：不再免费签发 |
| v4.0+ | 订单、支付、续费、发票 |

> 版本号冲突提示：早期讨论稿用 3.0=Agent / 3.3=收费 / 4.0=支付；本仓库 `novora-version-tasks.md` 用 v2.12=Agent、v3.3=智能诊断、v4.0+=商业化。两套编号必须先统一，建议以仓库文档为准，把"正式收费代码"提前到 Agent 之后的第一个版本。

## 7. 过渡策略

1. 内测期（Agent 首发起）：全部功能免费，但**照常签发 License**，只是不校验到期。
2. 转收费时：仅"不再免费签发新 License"，功能代码零改动。
3. 老学校：按首批内测学校赠送 6–12 个月专业版，避免"先免费用后突然收费"的反弹。

## 8. 三个坑

1. **单台控制指令已经免费存在**，Agent 的收费点必须放在批量、跨教室、定时、无人值守、异常自愈，不能重复收单台暂停/结束。
2. **License 必须提前埋**，否则收费时要么改大量功能代码，要么把已经免费送出去的能力再收回。
3. **备份恢复和升级不能收费**：收了钱也要修 bug，这类安全能力一旦收费，口碑与合规风险都不可控。

## 9. 开发差距（详细）

总览：

| 差距 | 对应版本 | 规模 | 是否收费前置 |
|---|---|---|---|
| A 考试管理收口 | v2.8.x | 中大 | 是（产品完整度） |
| B 设备身份与空间模型 | v2.9.x | 中大 | 是（Agent 前置） |
| C 镜像与灾备 | v2.10.x | 大 | 是（收费保险丝） |
| D 授权骨架 | v2.11.x | 小中 | 是 |
| E Agent | v2.12.x | 大 | 是（收费核心） |
| F 授权运营 | v3.x | 中 | 是（收费后立刻要用） |

### Gap A · v2.8 考试管理收口

**A1 迁移与回滚脚本（T-280-04）**

- 现状：schema 版本由 `api/_schemaMigration.ts` 记录（当前 auth=3、exams=4）；建表全靠运行时 `ensureTableOnce()` 的幂等 DDL；`migrations/` 目录只有一个 `0003_create_diagnostic_log_tables.sql`。
- 缺口：没有"版本号 → 迁移脚本"的执行器，没有回滚脚本，没有"空库 / 旧库 / 重复执行"三种路径的验证记录。
- 依赖：无，可与备份恢复并线做。
- 验收：空库、v2.7.x 旧库、重复执行都能正常启动；回滚不丢数据。

**A2 考试详情页与编辑入口（T-282-01/02）**

- 现状：`src/components/ExamRecordsPanel.tsx` 只有列表、筛选和搜索，全文件没有详情视图（无 detail / drawer / modal 结构）。
- 缺口：详情页（时间线、配置、适用范围、设备状态、操作记录）、从详情跳转现有大型考试编辑、返回时保留筛选条件。
- 依赖：A3 的操作日志（详情页要展示"谁在什么时候改了什么"）。
- 验收：从列表点进详情，编辑保存后详情自动同步。

**A3 考试级操作 API + 操作日志 + 控制面板（T-285-01/02/03/04）**

- 现状（已完成的部分）：`api/_exams/routes/examRecordRoutes.ts` 目前对外支持 `publish / end / archive / unarchive / copy`；`exam_record_operations` 表已在 `api/_exams/db.ts` 建好；并行会话刚落地第一批——`src/shared/examLifecycleOperations.ts` 生命周期操作规划器（含单测 `tests/examLifecycleOperations.test.ts`）、`exam_records` 暂停相关列、`exam_record_operations` 扩展列、投影与路由的 pause 字段映射（4 个提交，本地已完成、尚未推送）。
- 现状（仍未做）：操作日志表**仍无写入路径**，只在建表语句和 `/api/status` 的表清单里出现；客户端现有的暂停/继续/延时/结束走的是**设备级指令**（`src/shared/deviceContracts.ts` 的 `DEVICE_COMMAND_ACTIONS` + `DeviceStatusPanel`），作用对象是教室电脑，不是考试状态。
- 缺口：把操作规划器接到 `/api/exams` 的操作入口（start / pause / resume / extend / end，含权限与审计）、操作日志的写入与查询接口、考试控制面板 UI、状态异常提示（时间变更前后对比）。
- 依赖：无强依赖；与 v2.9 的设备在线状态配合体验更好。
- 验收：每个操作有权限检查和审计；重复操作幂等；控制面板可查历史操作。

**A4 发布前检查与发布记录（T-286-01/02）**

- 现状：考试公告已具备（`ExamAnnouncementOverlay` + announcements API）；没有发布前检查（时间冲突、设备在线、配置完整性）；发布记录只能靠通用审计日志。
- 缺口：发布前检查 API + 结果展示；发布记录（谁、何时、向哪些设备）。
- 依赖：A3 的操作日志；设备在线状态来自 v2.9 心跳。
- 验收：发布前能看到"哪台设备不在线、哪段时间冲突"，发布后能查到记录。

**A5 旧数据迁移端到端测试（T-286-04）**

- 现状：集成测试覆盖并发写、全局写槽、事务回滚、schema 迁移状态，但没有"v2.7.x 真实快照 → 升级后仍可读可编辑"的端到端用例。
- 缺口：一个以旧版快照为输入的升级回归用例。
- 验收：旧快照导入后，大型考试、周测、设备绑定、权限都正常。

### Gap B · v2.9 设备身份与空间模型（Agent 硬前置）

**B1 设备身份（T-290-01/02）**

- 现状：客户端用的是浏览器 `localStorage` 里的随机 UUID（现场抓包里是 `fc6de790-58e0-4ee6-ab65-b9a09d02a318` 这种形态），不是规划里的 `NOVORA-A8F2-001928`；`device_instances` 表存在，但以 instance_id 为主键、只绑年级/班级，没有设备名、房间号、客户端版本、创建时间等字段。
- 缺口：稳定的设备 ID 生成与展示、设备表字段扩展、注册与撤销 API。
- 验收：刷新与重装浏览器后 ID 规则可预期；服务端能列出设备的完整字段。

**B2 空间模型（T-290-03/04）**

- 现状：`api/_exams/db.ts` 与 `src/types/school.ts` 里都没有 campus / building / floor / room 概念，只有年级与班级；设备只能绑到班级。
- 缺口：`School → Campus → Building → Floor → Room → Device` 的模型与 CRUD API，设备绑定教室（Room → Class）。
- 依赖：B1。
- 验收：一台设备能定位到"某楼栋某教室"，并且教室能映射到班级。
- 备注：可以与 v2.10 并行；如果赶进度，先做"楼栋 + 教室"两级，Campus/Floor 后补。

**B3 本校错误存储（T-292-02）**

- 现状：服务端只把脱敏摘要转发给作者端，本地没有 `error_reports` 表，学校自己查不了历史错误。
- 缺口：本地错误表 + 指纹去重 + 次数统计 + 学校端查询。
- 优先级：可以后置，作者端错误中心已能满足作者侧运维。

**B4 学校运行日志 API（T-293-02）**

- 现状：运行日志只存在浏览器 `localStorage`（`src/utils/logger.ts`），作者端能管理学校手动上传的诊断包，但学校端没有"按设备/时间查日志"的接口。
- 缺口：学校侧日志查询 API（本地保留、脱敏、范围限制）。
- 优先级：可后置。

### Gap C · v2.10 镜像与灾备（收费保险丝）

- 现状：`docker-compose.yml` 的 app 服务是 `build: context: .`（在设备上现场构建）；`.github/workflows/docker-image.yml` 还是 GitHub 默认模板——只 `docker build`、打时间戳 tag、**从不 push**、只在 `main` 触发；没有升级执行体，也没有任何备份/恢复代码（只有方案文档 `novora-update-backup-plan.md`）。
- 缺口：CI 打 tag + 推镜像 + release manifest；compose 改为 `image:` + tag 变量；`novora-updater` sidecar（唯一持有 Docker socket、白名单操作）；一键升级与自动回滚；`.nbk` 备份/恢复/跨机恢复；`data/` 持久化挂载。
- 依赖：无（可与 Gap D 并行）。
- 验收：命令行先跑通 `backup → pull → migrate → health → rollback`，网页再复用同一套。

### Gap D · v2.11 授权骨架

- 现状：`src/shared/permissionRules.ts` 里只有角色权限（major/weekly/school/device/user/role/audit/deployment/diagnostics），没有任何 License、套餐或功能开关概念。
- 缺口：`License / Entitlement / Feature Flag` 数据结构与判断入口 `canUse()`；作者端签发、撤销、续期；内测期免费签发但全功能打开的流程。
- 依赖：无。
- 验收：新增一个付费标识时，只改 Entitlement 数据，不改功能代码。

### Gap E · v2.12 Agent（收费核心）

- 现状：完全没有。作者端目前只有实例概览与错误中心（`exam-board-telemetry` 侧，今天仍在推进趋势与报告）。
- 缺口：客户端本地服务（先 Windows）、注册密钥与撤销/恢复、心跳与指令队列 ACK、静默自动更新、控制分级 L1（页面）/L2（系统）/L3（高风险，默认禁用）、Agent 统计与分组。
- 依赖：B1/B2（设备身份与教室归属）、C（Agent 的更新与回滚通道）。
- 验收：一台教室电脑装上 Agent 后，作者端能按楼栋/教室看到它、能下发白名单指令、能远程升级并回滚。

### Gap F · v3.x 授权运营

- 缺口：到期/宽限/设备数**软限制**（提示 + 30 天宽限 + 只读，不硬断教学）；作者端运营台（学校列表、授权状态、到期时间、手工开通/延期/退款标记、审计）；灰度发布与版本分组。
- 依赖：D、E。
- 验收：运营台能回答"哪些学校什么时候到期、谁开通过、退过款、现在跑哪个版本"。

### 非代码差距（会卡住收费）

- 许可与合规：当前 `PikaNova/Novora-future` 是**公开仓库 + MIT 许可**，新版本需转专有许可；配套 EULA、隐私政策、退款政策。
- 运营准备：定价表、首批内测学校名单、支持渠道与响应承诺。
- 时间点：建议在 v2.12 完成前全部就位，不要等到收费当天。

## 10. 最短收费路径

```text
v2.10 镜像 + 升级回滚 + 备份恢复   ← 没有它不敢收钱
   ↓
v2.11 License 模型 + canUse        ← 内测免费签发、功能全开
   ↓
v2.12 Agent 可用并稳定              ← 收费核心就位
   ↓
v2.13 授权运营 + 停止免费签发        ← 实际开始收费（建议）
   ↓
v4.0 支付/订单/续费（可先人工收款）
```

可压缩项：

1. 空间模型先做"楼栋 + 教室"两级，Campus/Floor 后补。
2. v2.10（镜像）与 v2.11（License 数据结构）并行，省一个版本周期。
3. v2.9 的本校错误存储与运行日志 API 后置（作者端错误中心已够用）。
4. 内容包通道砍掉或后置——Agent 本身就是收费物。

关键路径：**空间模型与设备身份 → Agent；镜像与升级 → Agent 的更新回滚；License → 收费开关。**
